Data Preprocessing Pipeline: Overview & Usage Guide

This document outlines the data preprocessing pipeline applied to the weatherAUS.csv dataset and provides instructions on how to use the generated output files for model training.

1. Preprocessing Steps Applied
To ensure data integrity and prevent data leakage, the following pipeline was strictly executed:

    Target Cleaning: Removed records missing the target variable (RainTomorrow). Mapped binary text ('Yes'/'No') to integers (1/0) for RainToday and RainTomorrow.

    Feature Engineering: Extracted Month from the Date column to capture seasonal patterns, then dropped the raw Date string.

    Data Splitting: Split the dataset into Training (80%) and Testing (20%) sets prior to any transformations to prevent information leakage.

    Imputation: Filled missing numerical values using the Median, and categorical values using the Most Frequent (Mode) class.

    Quantification & Scaling: Applied One-Hot Encoding to categorical features (dropping the first column to prevent multicollinearity) and Standard Scaling to numerical features.

    Class Balancing: Applied SMOTE (Synthetic Minority Over-sampling Technique) exclusively to the Training set to correct the heavy class imbalance, achieving a 1:1 ratio for the target variable.

2. Output Files
The pipeline generates two final CSV files:

    train_preprocessed.csv: The fully quantified, scaled, and artificially balanced training dataset.

    test_preprocessed.csv: The quantified and scaled testing dataset, retaining the real-world class imbalance.

3. How to Use the Data
Both CSV files are now 100% numeric and contain zero missing values. They are ready for immediate use.

    Load the data using a library like Pandas (pd.read_csv).

    Separate the features (X) from the target (y = RainTomorrow).

    Train your models (Logistic Regression, kNN, LDA, etc.) exclusively on train_preprocessed.csv.

    Evaluate your models on test_preprocessed.csv. Because the test set reflects the natural imbalance of rainy vs. non-rainy days, it is highly recommended to use metrics like Precision, Recall, and F1-Score rather than plain Accuracy. No further data transformation is required before training.
